# Шаблоны заданий для кластера

**Статус: не проверены на реальной очереди.** Доступа к кластеру и его
параметров нет (решение D-005 в `docs/DECISION_REGISTER.md`), поэтому эти
файлы — заготовки с явными местами для подстановки, а не рабочие скрипты.
Ни одно число, полученное с их помощью, не должно попадать в отчёт до того,
как прогон реально выполнен и его манифест сохранён.

Что нужно узнать у владельца ресурса перед первым запуском:

| параметр | зачем |
|---|---|
| планировщик и версия (SLURM / PBS / …) | синтаксис директив |
| account, partition/queue | без них задание не примут |
| лимиты: время, память, число узлов | размер кампании |
| спецификация узла: ядра, сокеты, память | нормировка и привязка потоков |
| модули компилятора и MPI | воспроизводимость сборки |
| наличие и модель GPU | фаза T12 (сейчас заблокирована) |

Заполненные значения фиксируются в `docs/DECISION_REGISTER.md` (D-005), а не
только в скриптах, — иначе кампанию нельзя будет воспроизвести.

## Принципы, которых держатся шаблоны

1. **Сборка внутри задания.** Бинарник собирается на том же узле, где
   считает: иначе неясно, что именно измерено.
2. **Манифест на каждый прогон.** Записываются коммит, модули, узел, число
   рангов и потоков — `scripts/benchmark.py` делает это сам.
3. **Прогрев отбрасывается, повторов не меньше пяти**, отчитывается медиана
   с MAD. Одно измерение непригодно.
4. **Проверка корректности вместе с замером.** Прогон, изменивший ответ,
   ускорением не считается: сравниваются диапазоны `rho`/`p` с серийным.
5. **Неудачные прогоны сохраняются**, а не удаляются.
