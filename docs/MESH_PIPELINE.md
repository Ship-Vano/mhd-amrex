# LEG-003 — воспроизводимый сеточный конвейер

Дата: 2026-09-03.

## Статус

Ранее было зафиксировано, что «Netgen на этом хосте отсутствует/сломан», и все
прогоны `legacy_corrected` шли на структурной прямоугольно-треугольной сетке.
Это оказалось **неверным диагнозом**: пакет `netgen-mesher` установлен, а падал
он из-за отсутствия `numpy` в системном интерпретаторе — `libngpy`
инициализируется только при доступном numpy, и сообщение
`ImportError: initialization failed` этого не проясняло.

Конвейер восстановлен.

## Установка (закреплённая)

```
python3 -m venv .venv-netgen
.venv-netgen/bin/pip install numpy netgen-mesher
.venv-netgen/bin/python -c "import numpy, netgen; from netgen.geom2d import SplineGeometry"
```

Проверено с `netgen-mesher` версии `6.2.2506` и `numpy` `2.0.2`
(macOS, Apple Silicon, CPython 3.9).

## Использование

```
python3 scripts/run_legacy_corrected.py \
    --source /path/to/MHD2D --case rotor \
    --mesh-backend netgen --netgen-python .venv-netgen/bin/python \
    --maxh 0.012 --artifact-dir benchmarks/raw/legacy_corrected/rotor_netgen
```

Пример метаданных сетки (полоса Брио–Ву, `maxh` 0.0025):

```json
{"generator": "Netgen", "netgen_version": "6.2.2506",
 "nodes": 4013, "triangles": 7208, "grading": 0.3,
 "quality": {"min_angle_degrees": 37.73, "max_radius_ratio": 1.3018}}
```

## Зачем это важно численно

Структурная сетка из прямоугольных треугольников — особый случай, и на нём
часть ошибок **не видна**. Конкретный пример из этой работы: в исходной
инициализации вихря Орзага–Танга нормальная компонента `B_n` бралась
сэмплированием в середине ребра. Для поля вида `Bx = f(y)`, `By = g(x)` на
такой сетке слагаемые контурной суммы попарно сокращаются, и начальная
дивергенция получается нулевой **случайно**. На произвольной триангуляции
сокращения нет, и поле не является дискретно бездивергентным.

Это измерено. На нерегулярной сетке Netgen (5790 треугольников,
`h_max` = 0.0294) начальная `max|div B|` для поля Орзага–Танга:

| задание `B_n` | `max\|div B\|` | нормированная |
|---|---:|---:|
| сэмплирование в середине ребра (исходный код) | `8.944e-02` | `6.60e-03` |
| разности узлового `A_z` (исправленный код) | `5.336e-15` | `3.94e-16` |

Разница — **13 порядков**. На структурной сетке обе формы дают округление, то
есть дефект там не наблюдаем в принципе.

Поэтому:

- две карты (`task_type` 4 и 5) переведены на задание `B_n` через разности
  узлового векторного потенциала `A_z` — это корректно на любой сетке;
- нерегулярная сетка Netgen нужна как **стресс-тест**, а не как косметика:
  именно она отличает «схема верна» от «сетка удачная».

## Прогон на нерегулярной сетке

Вращающийся цилиндр, `maxh` 0.012 (16242 треугольника, минимальный угол 37.8°),
`benchmarks/raw/legacy_corrected/rotor_netgen/`, quality gate — **pass**:

- начальная невязка магнитного потока `1.93e-16`, конечная `5.16e-16`;
- нормированный дисбаланс потока `1.02e-14`;
- `ρ ∈ [0.711, 8.006]`, `p ∈ [0.0585, 1.815]`;
- 1 откат HLLD→HLLE — нерегулярная сетка ожидаемо жёстче структурной.

## Ограничение
