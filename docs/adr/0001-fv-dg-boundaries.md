# ADR 0001 — Модульные границы FV-решателя и задел под DG

- **Статус:** принят
- **Дата:** 2026-09-03
- **Гейт:** TDG0 / G-EXT0; требования EXT-001, EXT-003
- **Контекст фазы:** T14 (завершение), до начала любой работы по DG

## Контекст

`PROGRAM_PLAN` (EXT-001) требует зафиксировать модульные границы до того, как в
проект попадёт разрывный метод Галёркина (DG). Опасность конкретна: если
DG «прорастает» внутрь FV-кода в виде рантайм-ветвлений `if (dg) ...`, то
(а) каждая FV-регрессия начинает зависеть от кода, который никто не исполняет,
(б) численный результат FV перестаёт быть воспроизводимым между ревизиями.

Решение принимается **до** появления DG и намеренно ничего под него не
реализует: спекулятивный фреймворк — это тоже долг.

## Решение

Границы проходят там, где они уже фактически проходят в дереве исходников.
ADR закрепляет их и делает нарушение обнаруживаемым.

### 1. Физика и численные ядра — `src/kernels/*.H`

Единственный слой, который DG будет переиспользовать без изменений.

| Заголовок | Контракт |
|---|---|
| `MhdState.H` | раскладка консервативных/примитивных величин (`ConsVar`, `PrimVar`), `cons_to_prim`, `prim_to_cons`, `fast_speed`, `Limits` (полы `rho`, `p`) |
| `Hlld.H` | `mhd_wave_speeds`, `hll_flux`, `hlld_flux_raw` (предикат допустимости), `hlld_flux` (обёртка с откатом и счётчиком) |
| `Reconstruction.H` | лимитеры и MUSCL-реконструкция на грань |
| `CtUpdate.H` | угловая ЭДС и обновление граневого поля по Стоксу |

Правила слоя:

- **функции чистые**: аргументы — сырые массивы `double*`/`Real*` и скаляры, без
  контейнеров AMReX (`MultiFab`, `Box`, `Array4`, `MFIter`);
- **никакого владения памятью и никакого I/O**;
- допускается ровно две зависимости от AMReX — `AMReX_REAL.H` (тип `Real`) и
  `AMReX_GpuQualifiers.H` (макрос `MHD_HD` для будущего device-кода). Обе —
  типовые/атрибутные, не структурные: они не тянут модель данных;
- поэтому слой собирается **вне** AMReX. Это не декларация: цели
  `mhd2d_kernel_unit`, `mhd2d_kernel_numerics` и `mhd2d_verify` компилируются
  без линковки с AMReX (`CMakeLists.txt`) и служат контрактными тестами слоя
  (EXT-003).

### 2. Пространственный оператор — `MhdAmr::ComputeFluxesAndEmf`, `ApplyUpdates`

Здесь и только здесь ядра встречаются с раскладкой данных AMReX. DG заменит
именно этот слой (свой оператор объёма/поверхности), сохранив слой 1.

### 3. Интегратор по времени — `MhdAmr::AdvanceHierarchy`

Оператор `L(U)` вызывается через `EulerStage`. Интегратор ничего не знает о
способе дискретизации по пространству и переиспользуется DG как есть.

### 4. Сеточный бэкенд

Два независимых бэкенда с общим набором тестовых карт:
декартова иерархия AMReX (`MhdAmr`) и неструктурированная треугольная сетка
исторического решателя (`legacy/`, оверлей + `scripts/run_legacy_corrected.py`).
Обмен между ними идёт **только** через файлы результатов и сравнивающие скрипты
(`scripts/compare_*.py`, `scripts/slice_compare_2d.py`), а не через общий API.

### 5. Диагностика и конфигурация

`SimConfig` (`src/Config.*`) — единственный источник параметров расчёта; схема
строгая, неизвестный ключ отвергается (`config.rejects_unknown_key`).
Диагностики (`MaxDivB`, `TotalConserved`, `PrintStateRanges`,
`CountNonPositiveCells`, счётчик откатов HLLD) печатаются в одном формате
`ключ=значение`, что и позволяет тестам на Python работать как гейтам.

## Карта зависимостей

```
Config ──────────────► MhdAmr ──────► AMReX (AmrCore, MultiFab, YAFluxRegister)
                         │
Problems (НУ через Az) ──┤
                         ▼
                    kernels/*.H          ◄── mhd2d_verify, kernel_unit,
              (без AMReX-контейнеров)         kernel_numerics  [сборка без AMReX]
```

Стрелок из `kernels/` наружу нет — это и есть проверяемый инвариант.

## Следствия

- DG добавляется как **новый** пространственный оператор рядом с существующим,
  повторно используя слой 1; FV-путь не получает ни одного рантайм-ветвления.
- Плата: раскладка `double[NCONS]` в ядрах не оптимальна для DG-квадратур —
  принимается сознательно, менять раскладку будем при реальной необходимости.
- Обязательство гейта TDG0: FV-регрессии дают прежний результат. На момент
  принятия ADR никакого DG-кода, заглушек и флагов в дереве нет —
  `grep -ri "\bdg\b" src/` не находит ни одного вхождения.

## Проверка

`ctest -R kernel.` собирает и исполняет слой 1 в отрыве от AMReX; если в
`src/kernels/*.H` попадёт структурная зависимость от AMReX, эти цели перестанут
компилироваться. Дополнительно `tests/check_kernel_purity.py` (CTest
`arch.kernel_purity`) проверяет список разрешённых `#include` в слое.
