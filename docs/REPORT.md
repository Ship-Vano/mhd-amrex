# Расчётно-пояснительная записка НИРС: текущий статус 2D ideal-MHD solver

Дата draft: 2026-08-26. Исходная ревизия доказательств: `40ebbae`.

## Аннотация

В проекте реализуется новый 2D/2.5D решатель идеальной МГД на AMReX и
сохраняется независимый legacy baseline. В новом CPU-коде присутствуют HLLD,
MUSCL-реконструкция, staggered constrained transport (CT), а также
двухстадийный SSP-RK2/Heun (TVD RK2 Шу--Ошера) [C-001]. Параметры задач
задаются JSON-файлами [C-002]. На текущей машине прошли два standalone
smoke-запуска, но они являются только диагностикой [C-003, C-004]. Полная
численная верификация, консервативность AMR, GPU-порт и benchmark ещё не
заявляются [C-005--C-011]. Полная трассировка утверждений приведена в
[claim-to-evidence matrix](CLAIM_TO_EVIDENCE.md).

## Цель

Нужно построить доказательную базу для сравнения двух независимых продуктов:

- `mhd2d_legacy` — исторический неструктурированный finite-volume baseline;
- `mhd2d_amrex` — новый блочно-структурированный solver;
- общий контур validation и benchmark.

Исследовательская гипотеза H1: AMReX-вариант *может* обеспечить лучшее
соотношение ошибки, времени и памяти. Она не считается доказанной и будет
проверяться раздельно при equal resolution, equal cost и equal error [C-008].

## Реализованная постановка

Рассматриваются уравнения идеальной МГД в нормировке без множителей `4π`:

```text
∂ρ/∂t + ∇·(ρv) = 0
∂(ρv)/∂t + ∇·(ρvv + pT I − BB) = 0
∂E/∂t + ∇·((E+pT)v − B(v·B)) = 0
∂B/∂t = ∇×(v×B),  ∇·B = 0
```

В 2.5D-режиме решение зависит от `(x,y,t)`, а скорость и магнитное поле имеют
три компоненты. `rho`, импульс, энергия и `Bz` хранятся в центрах ячеек;
`Bx/By` — на гранях; `Ez` — в узлах [C-001].

Одна реализованная стадия строит MUSCL-состояния, получает HLLD-потоки и
граневые ЭДС, усредняет ЭДС в узлы, обновляет газовые величины конечными
объёмами и `Bx/By` законом Фарадея. Временной интегратор уже является
SSP-RK2/Heun; заменять его на midpoint RK2 не требуется [C-001]. Наличие
формулы в исходном коде не заменяет branch/degeneracy tests HLLD и
convergence tests: они входят в T04.

## Известные ограничения

1. На coarse--fine границах нет gas flux register/reflux. Поэтому нельзя
   утверждать глобальную консервативность AMR [C-005].
2. Низкая `divB` норма на однородных smoke-задачах не доказывает гарантии на
   всей AMR-иерархии [C-006].
3. GPU-путь не реализован: hot loops используют `amrex::LoopOnCpu`; device
   qualifiers в заголовках сами по себе не выполняют kernels на GPU [C-007].
4. Архив legacy/results найден, но не имеет точной связи `commit + config +
   mesh + physical time + result`; исторические числа ВКР не воспроизведены
   [C-009].
5. Brio--Wu может содержать физические составные структуры. До выбора
   regular или compound/non-regular reference нельзя называть любой экстремум
   численной осцилляцией [C-010].

## Вывод

Кодовая основа нового решателя реализована и запускается в CPU Release
конфигурации [C-001--C-004]. Достоверный научный вывод пока ограничен этим
фактом: верификация, AMR-консервативность, GPU и преимущество над legacy
остаются работами с явными gate. Такой статус не скрывает отрицательных или
неполных результатов и делает следующую проверку воспроизводимой.
