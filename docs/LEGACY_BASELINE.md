## 2. Воспроизводимость текущего legacy-снимка

Проверено на текущей машине:

1. CMake-конфигурация Release проходит AppleClang 17.
2. OpenMP не обнаруживается, но CMake продолжает конфигурацию, поскольку
   `find_package(OpenMP)` не является обязательным.
3. Сборка затем падает на безусловном `#include <omp.h>` в
   `NetGeometry.h`. Это дефект согласования CMake и исходников, а не результат
   численного теста.
4. В Git-истории отсутствуют `InputData/solverConfig.json`,
   `InputData/mesh.txt`, `OutputData/` и генератор Gmsh, хотя исполняемый файл
   требует первые два объекта при запуске.
5. Поэтому ни CPU-, ни GPU-результат из данного commit пока не воспроизведён.

Для честной baseline-сборки нужен изолированный Linux toolchain с OpenMP и
восстановленные входные данные. Исправления portability следует хранить как
отдельный adapter/patch, не переписывая зафиксированный legacy commit.

## 3. Устройство прежней схемы

| Свойство | `MHD2D` commit `9d0f60e` | `mhd-amrex` на момент аудита |
|---|---|---|
| Сетка | статическая неструктурированная треугольная | блочно-структурированная Cartesian AMReX |
| Пространство | piecewise constant finite volume | MUSCL, MC/minmod/van Leer |
| Поток | HLL/HLLC/HLLD в 1D, HLLD в 2D | HLLD |
| Время | forward Euler | SSP-RK2/Heun (TVD RK2 Шу–Ошера) |
| Магнитное поле | cell state + нормальный `Bn` на рёбрах | `Bx/By` на гранях, `Bz` в ячейках |
| CT | узловая ЭДС как среднее потоков прилегающих рёбер | Balsara–Spicer или сокращённый Gardiner–Stone |
| Восстановление `B` | базис Raviart–Thomas из edge-normal `Bn` | полусумма противоположных граней |
| AMR | нет | есть, но gas reflux пока отсутствует |
| MPI | нет | AMReX/MPI |
| CPU parallelism | OpenMP преимущественно в построении геометрии | AMReX CPU path; scaling ещё не измерен |
| GPU | CUDA-файлы есть, исполняемый путь отключён | CUDA-порт ещё не реализован |
| Вывод | VTU | AMReX plotfile/HDF5 |

Legacy хранит

```text
U = (rho, rho*u, rho*v, rho*w, E, Bx, By, Bz),
E = p/(gamma-1) + rho*|v|^2/2 + |B|^2/2.
```

То есть в коде магнитное поле уже нормировано так, что множитель `4π` поглощён.
Это совпадает с соглашением нового ядра, но должно проверяться на каждом
адаптированном тесте, поскольку в тексте ВКР отдельные физические постановки
записаны с явным `4π`.

### Существенные свойства реализации

- 1D HLLD и 2D gas update используют один шаг forward Euler.
- Функция minmod существует, но `applyLimiter` нигде не вызывается: текущая
  legacy-схема фактически первого порядка по пространству.
- CPU HLLD заменяет две нормальные компоненты поля Roe-взвешенным средним,
  тогда как новое ядро передаёт единственное staggered `Bn`. Для Brio–Wu,
  где `Bx_L=Bx_R`, это не меняет вход, но для общих тестов реализации различны.
- В CUDA-копии HLLD правая скорость задана через `min(uL,uR)+max(cfL,cfR)`,
  а в CPU-коде корректно используется `max(uL,uR)+max(cfL,cfR)`. До
  исправления и parity-теста CPU/GPU legacy численно не эквивалентны.
- 2D HLLD вычисляется после поворота состояний в локальную систему ребра.
- Gas variables обновляются суммой потоков по трём рёбрам треугольника.
- Узловая ЭДС получается простым арифметическим средним соответствующей
  компоненты HLLD-потоков прилегающих рёбер; закомментированная логика upwind
  orientation не действует.
- Edge-normal `Bn` обновляется законом Фарадея, затем `Bx/By` в центре
  восстанавливаются через Raviart–Thomas.
- Нет positivity fallback и счётчиков отрицательных `rho/p`; проверяются только
  NaN после шага.
- `computeDivergence()` ищет максимум знакового значения, а не
  `max(abs(divB))`; отрицательный наибольший по модулю дефект может быть скрыт.
- В актуальной 2D постановке Brio–Wu код принудительно ставит CFL `0.9`, тогда
  как ВКР сообщает CFL `0.1`. Это разные конфигурации.
- 1D driver не подрезает последний `dt` к `t_end`, а также называет значения
  «узлами», хотя обновляет их консервативной разностью межузловых потоков.
  В adapter нужно зафиксировать геометрический смысл данных и единый output
  time, а не сравнивать последние записанные слои как есть.

## 4. Фактический статус параллельного кода legacy

Пять циклов построения геометрии используют корректные директивы
`#pragma omp parallel for`. В решателях многие директивы записаны как
`#pragma parallel for` без `omp` либо закомментированы; стандартный компилятор
их игнорирует. Поэтому нельзя считать 2D time loop полноценно
OpenMP-параллельным без отдельной проверки профилем и thread-scaling.

CUDA-исходники реализуют device HLLD и host wrapper, но в текущем commit:

- вызов `solver.runGPUSolver()` в `solver.cpp` закомментирован;
- вызов `computeHLLDFluxesGPU()` внутри `runGPUSolver()` закомментирован;
- при выборе `gpu=true` основной расчёт фактически не запускается;
- даже при прямом вызове `runGPUSolver()` массивы потоков остались бы нулевыми.

Следовательно, исторические GPU-цифры из ВКР нельзя приписывать текущему
commit без поиска соответствующей ревизии и повторного запуска.

## 5. Данные, извлечённые из ВКР

### Brio–Wu

Историческая постановка:

- область `x in [-0.5, 0.5]`, узкая 2D-полоса;
- `gamma = 2`, `Bx = 0.75`;
- лево: `(rho,p,u,v,w,By,Bz) = (1,1,0,0,0,1,0)`;
- право: `(0.125,0.1,0,0,0,-1,0)`;
- frozen («исторические») граничные значения;
- основной график: 400 узлов, `dx=0.0025`, CFL `0.1`, `t=0.1`;
- convergence study: `N=64,128,256,512`, self-reference `N=1024`.

Опубликованная в ВКР таблица усреднённой ошибки HLLD:

| N | Ошибка | Наблюдаемый порядок |
|---:|---:|---:|
| 64 | 0.199094 | — |
| 128 | 0.141322 | 0.494463 |
| 256 | 0.081178 | 0.799816 |
| 512 | 0.033738 | 1.266706 |

Эти значения являются историческими данными автора, а не воспроизведённым
benchmark. Определение «усреднённой ошибки» в новом harness нужно сделать
явным; self-reference на 1024 узлах недостаточен для классификации составной
волны и паразитных экстремумов.

### Исторические CPU/GPU времена

ВКР указывает Intel Core i5-4440, GeForce GTX 960 4 GB и 16 GB RAM; около 30%
вычислений выполнялось на GPU, построение геометрии не включалось.

| Случай | CPU, 1 ядро | CPU + GPU | Историческое ускорение `Tcpu/Tgpu` |
|---|---:|---:|---:|
| Alfvén wave, N=128 | 765.1 s | 538.7 s | 1.420 |
| Orszag–Tang, N=400 | 482.4 s | 342.13 s | 1.410 |
| rotating cylinder, N=400 | 303.7 s | 215.39 s | 1.410 |

Неизвестны число повторов, разброс, точная ревизия, compiler flags, состав

как baseline для публикации нового ускорения.

## 6. Протокол прямого сравнения

Сравнение разбивается на два уровня.

### Уровень A: чистое сравнение порядка схем

Использовать 1D HLLD legacy и uniform driver нового проекта на одной сетке:

1. одинаковые состояния, `gamma`, область, frozen BC, CFL `0.1`, `t=0.1`;
2. legacy: piecewise constant + Euler + HLLD;
3. новый N0: piecewise constant + Euler + HLLD;
4. новый N1/N2/N3: MUSCL, затем SSP-RK2, затем выбранная CT-ЭДС;
5. общий независимый reference и единый sampling/projection protocol;
6. отдельно разрешить неоднозначность legacy «узлы» против AMReX cell averages
   и гарантировать точное попадание обоих кодов в `t=0.1`.

Этот уровень отделяет изменение HLLD-реализации от MUSCL и интегратора.

### Уровень B: полные 2D решатели

Сгенерировать версионируемую прямоугольную полосу из согласованных пар
треугольников для legacy и Cartesian strip для AMReX. Хранить:

- число контрольных объёмов и эффективный `dx` отдельно;
- площадь каждого legacy-элемента;
- area-weighted проекцию треугольных данных на общие x-bins;
- одинаковые x-BC и периодические y-BC;
- одинаковое физическое конечное время и output time.

Из-за разной топологии обязательны четыре представления: equal spacing,
equal DoF, equal compute cost и equal error. Сравнение только `N=400` против
`n_cell=400` некорректно.
